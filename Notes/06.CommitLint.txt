COMMIT MESSAGE RULES (commitlint + husky)

Goal: a good message is accepted, a bad one is rejected BEFORE the commit is made.

  fix: someFixHere        -> accepted
  somethingFixed          -> rejected, with a plain-English explanation (section 3)

Tools used:
- Husky and commitlint

Husky:
- a tool that manages git hooks inside the repo
- husky stores them in .husky/

commitlint:
- checks a commit message against a set of rules
- this repo uses the Conventional Commits rules from @commitlint/config-conventional, 
  set in commitlint.config.js. 

Error message is thrown by commitlint.formatter.js
